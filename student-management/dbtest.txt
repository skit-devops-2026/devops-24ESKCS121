# Student Management System — Authentication, Student CRUD, and Teacher Management Test Report

## 1. Authentication Tests

### Test 1: Student Registration and Login
- **Test:** Register a new Student using valid details.
- **Expected:** Student account is created, password is hashed, and a JWT token is returned.
- **Result:** Passed.

### Test 2: Duplicate Registration
- **Test:** Register again using an existing email or username.
- **Expected:** Request is rejected with an appropriate duplicate-account message.
- **Result:** Passed.

### Test 3: Teacher Registration
- **Test:** Register a new Teacher with department and designation.
- **Expected:** Teacher account is created with `approvalStatus: pending`; no login token is issued during registration.
- **Result:** Passed.

### Test 4: Pending Teacher Login
- **Test:** Attempt to log in as a Teacher before Admin approval.
- **Expected:** Login is blocked with an Admin-approval message.
- **Result:** Passed.

### Test 5: Incorrect Password
- **Test:** Log in using a valid username and an incorrect password.
- **Expected:** Request is rejected with `401 Unauthorized`.
- **Result:** Passed.

### Test 6: Password Hashing
- **Test:** Inspect stored Student and Teacher password values in MongoDB.
- **Expected:** Passwords are stored as bcrypt hashes, not plaintext.
- **Result:** Passed. Stored passwords had the bcrypt `$2b$` prefix and 60-character hash format.

### Test 7: Admin Account Creation and Login
- **Test:** Create an Admin through the trusted setup script and log in with the configured credentials.
- **Expected:** Admin account is created with `approvalStatus: approved`; login returns a JWT and Admin role.
- **Result:** Passed.

### Test 8: Admin Approves Teacher
- **Test:** Admin sends a `PATCH` request to the Teacher approval endpoint.
- **Expected:** Teacher's `approvalStatus` changes from `pending` to `approved`.
- **Result:** Passed. The route is now `PATCH /api/admin/teachers/:id/approve`.

### Test 9: Approved Teacher Login
- **Test:** Log in as a Teacher after Admin approval.
- **Expected:** Login succeeds and the returned user has `approvalStatus: approved`.
- **Result:** Passed.

### Test 10: Student Cannot Approve Teacher
- **Test:** Send the Teacher approval request using a Student JWT.
- **Expected:** Request is rejected with `403 Forbidden`.
- **Result:** Passed.

### Test 11: Invalid JWT
- **Test:** Send the Teacher approval request with an invalid token.
- **Expected:** Request is rejected with `401 Unauthorized`.
- **Result:** Passed.

### Test 12: Public Admin Registration
- **Test:** Attempt to register an Admin through `/api/auth/register`.
- **Expected:** Request is rejected with `400 Bad Request` and the message `Only Student and Teacher registration is allowed.`
- **Result:** Passed.

### Test 13: Rejected Teacher Login
- **Test:** Attempt to log in as a Teacher whose application has been rejected.
- **Expected:** Login is blocked with a rejection message.
- **Result:** Passed.

## 2. Student CRUD API Tests

### Test 14: Retrieve All Students
- **Endpoint:** `GET /api/students`
- **Test:** Retrieve the student list using an Admin JWT.
- **Expected:** Return `200 OK` with the student count and student records.
- **Result:** Passed.

### Test 15: Retrieve Student by ID
- **Endpoint:** `GET /api/students/:id`
- **Test:** Retrieve an existing student using a valid MongoDB ObjectId.
- **Expected:** Return `200 OK` with the student's public details.
- **Result:** Passed.

### Test 16: Invalid Student ID
- **Endpoint:** `GET /api/students/:id`
- **Test:** Send a request using an invalid ID such as `invalid-id`.
- **Expected:** Return `400 Bad Request` with `Invalid student ID.`
- **Result:** Passed.

### Test 17: Create Student
- **Endpoint:** `POST /api/students`
- **Test:** Create a student using valid details and an authorized Admin token.
- **Expected:** Return `201 Created` with the new student's public details. The password must not appear in the response.
- **Result:** Passed.

### Test 18: Update Student
- **Endpoint:** `PUT /api/students/:id`
- **Test:** Update a student's academic year to `3rd Year`.
- **Expected:** Return `200 OK` with `Student updated successfully.` and the updated academic year.
- **Result:** Passed.

### Test 19: Duplicate Email or Username During Update
- **Endpoint:** `PUT /api/students/:id`
- **Test:** Submit an update that conflicts with an existing email or username.
- **Expected:** Return `409 Conflict` with `Email or username is already registered.`
- **Result:** Conflict response observed during manual testing. Confirm the request used an existing email or username before treating this test as fully verified.

### Test 20: Delete Student
- **Endpoint:** `DELETE /api/students/:id`
- **Test:** Delete a test student using an Admin JWT.
- **Expected:** Return `200 OK` with `Student deleted successfully.`
- **Result:** Passed. The test student was deleted successfully.
